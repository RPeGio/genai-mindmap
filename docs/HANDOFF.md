# 交接文档（需要对方知悉或确认的决策）

**这个文件解决什么问题**：一个人先做了决定、但另一个人还不知道或不认同时，这个决定会悄悄变成"既成事实"。
等到发现时，代码已经按它写完了，改回去的成本远高于当初问一句。
所以凡属这类决策，先在这里登记一行，等对方点头，再动手落地或合入。

**和 `NEXT-PLAN.md` 的分工**：`NEXT-PLAN.md` 是陈嘉涛的个人评估稿（不入库），里面的待确认项在 2026-11-03 已回填到 `docs/PLAN.md` 的 Q35 / Q36。
今后**新的**待确认决策统一记在本文件，不再散落在个人草稿里。

## 使用规则

1. **谁决定的，谁登记**：在「待确认」表加一行，四件事必须写清——决策是什么、为什么要这么做、影响哪些文件或接口、**对方没回复期间默认怎么做**（没有这一条，事情就会卡住）。
2. **对方确认后**把该行移到「已确认」，状态写依据（PR 号 / 提交号 / 会议结论），不写"已确认"三个字了事。
3. **对方否决或改了方案**：原行改成「已否决」并写新的替代决策指向，不要直接删——被否掉的方案本身就是信息，能防止有人再提一次。
4. 本文件只放**跨人**的决策。纯粹的代码细节、只影响自己那条线的取舍，写进提交信息或代码注释即可。
