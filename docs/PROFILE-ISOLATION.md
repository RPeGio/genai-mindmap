# 画像方向按导图隔离

改动：`backend/app/prefs/profile.py`、`backend/app/agent/tools.py`。
验收：`backend/tests/test_prefs_profile_isolation.py`。
实测：`backend/scripts/measure_profile_isolation.py --run`。

## 为什么

`profile_vectors` 里的方向曾经是**全局**的：从库里全部材料、全部导图、全部记忆
聚出来的 3–5 根向量，任何一次检索都拿它们加权。后果是一张讲机器学习的图，检索
时会被"碳中和"那个方向加分——用户写「机器学习」，却看到碳中和的引用被顶上来。
那批被顶上来的碳中和材料随后又成为新样本，于是**越用越窄**。这就是过滤气泡，
只是它发生在**图与图之间**，不是人与人之间。

所以把内容方向按图隔离，而 `style`（统计层，8 个结构参数）不动：那 8 个数是
"这个人怎么做事"，该跨图；内容方向是"这张图讲什么"，不该跨图。

## 池键：`map_id` 还是 `run_id`

**判据：有 `map_id` 用它，没有用 `run:<run_id>`。**

新图在服务端**根本没有 id**——`repository.create_map` 才发 uuid4（`SaveRequest`
的注释写着"第一次保存之前没有 map_id"），`DiagramContent` / `AgentRunRequest` /
`RunContext` 三处都没有这个字段。生成发生在保存之前，所以生成链路拿不到一个还
不存在的东西。

- 纯 `map_id` 的后果：**首次生成永远没有池**，而那恰恰是最需要个性化的一刻
  （用户刚传完 3 份材料，问了一句话）。
- 纯 `run_id` 的后果：已保存图的多轮生成（`expand` / `edit`）各算一次。听起来
  更糟，但聚类是**确定性**的（最大最小距离初始化，没有随机数），同一批材料两轮
  算出同一批方向——池键只决定"存在哪一行、按谁读回"，不决定"算出来是什么"。

所以接口按"`map_id` 优先"设计，等生成链路能拿到它时直接生效。而 `run:` 不是
过渡形态：**"新图还没保存"这个状态会永远存在**（每次 create 都是它）。

## 数据

`profile_vectors` 加 `map_id TEXT`（`ensure_schema` 用 `repository._ensure_columns`
补列，老库不用改）。三种取值：

| `map_id` | 含义 | `stored(map_id=…)` 返回 |
|---|---|---|
| `NULL` | 隔离之前那批全局方向 | 只有 `map_id=None`（全量视图）能看到 |
| `''` | 显式要"全局池" | `stored(map_id="")` |
| `run:<id>` / `<uuid>` | 一个池 | 只这条池 |

`stored()` / `boost(directions=…)` 的参数**都没有默认值**，漏传是 `TypeError`。
这是刻意的：那个 bug 的形状就是"漏传一个参数，静默退化成全局"。

`rebuild(map_id)` 只清自己那个池（`DELETE … WHERE map_id = ?`），主键从 `d0` 改成
`{pool}#d{index}`——否则第二个池的第一条方向会撞主键，静默写不进去。

## 成本：那 6 次往返去哪了

旧路径从三张表取 60 条"文件名 + 前 600 字"的**拼接文本**再去 embed。那批文本
从来没人 embed 过（`chunk_vectors` 存的是**块**的向量），所以每条都是 cache miss：

```
60 条 ÷ embedding.MAX_BATCH(10) = 6 次 HTTP          ← 默认关的全部理由
```

新路径的样本换成这张图自己的**块**，而块向量检索时已经写进 `chunk_vectors` 了：

```
这张图的材料 → _chunk_tree 切块 → level=1 子块 → text_hash → chunk_vectors 查
                                                                  ↑ 0 次 HTTP
```

本机实测（`data/mindmaps.db`，18 份来源 / 80 个子块）：**子块命中 76 条 = 95%**，
父块只有 21%（父块只在 `search_sources` 单级路径下被 embed）。没命中的**不补
embed**——那是"零成本"的全部含义。

于是默认开关那条理由（"打开之后每次生成会多出 N 次 embedding 往返"）**不再成立**。
默认值仍不改在这一轮：先让数据说完话。

## 实测：两张不同主题的图

上一版 A/B（`measure_profile_ab.py --ab`）是**同一主题跑三次**，A 组关画像、
B 组开画像。它测不出跨图污染——没有第二张图，那个数恒为 0。这一版用两张：

```
图 A「机器学习的主要方向」  ml-监督学习 / ml-无监督 / ml-神经网络
图 B「碳中和政策」          cn-双碳目标 / cn-碳市场 / cn-低碳技术
```

两张图都用 `library=True` 检索（这是污染**唯一**能发生的路径：候选池 = 本次
材料 + 库里 `LIBRARY_PICK=5` 份，图 B 检索时库里剩下的正好是图 A 的三份）。

指标定义（第一版指标设计错过一次，记在这里）：

- ~~跨图命中的**条数**~~ 不成立：`boost` 的约束 1 是"不增不减"，条数在加权前后
  恒等，两组必然一样。
- ~~跨图命中的**名次改善**~~ 也不成立：名次会互相挤压，一分没加的那条也会因为
  别人被压下去而相对上升。
- **跨图命中实际拿到的画像加分**（`Boost.bonuses`）——只有它能归因。

真跑（MaaS embedding，20 条块向量预热；`embed_texts` 调用次数由脚本计数）：

| 组 | 方向数 | 候选 跨图/本图 | **跨图加分** | 本图加分 | 跨图登顶 | 方向成本 | 检索成本 |
|---|---|---|---|---|---|---|---|
| 碳中和 / 全局 | 3 | 2 / 3 | **0.0903** | 0.2591 | 否 | 1 次 / 6 条 | 1 次 / 1 条 |
| 碳中和 / 隔离 | 3 | 2 / 3 | **0.0000** | 0.2099 | 否 | **0 次** | 0 次 |
| 机器学习 / 全局 | 3 | 1 / 4 | **0.1267** | 0.1389 | **是** | 0 次（缓存命中） | 1 次 / 1 条 |
| 机器学习 / 隔离 | 3 | 1 / 4 | **0.0000** | 0.2486 | 否 | **0 次** | 0 次 |

三件事：

1. **跨图污染归零**：隔离之后另一张图的命中拿到的画假加分是 0，不是"少一点"。
   同一批命中在全局那组拿到 0.09–0.13，并且在机器学习那一组**被顶到第 1 名**。
2. **本图贴合没有变差**：0.2591 → 0.2099、0.1389 → 0.2486。隔离之后方向的余弦
   更高（0.92–0.96 vs 0.84–0.91），所以"加分总额"里属于本图的比例上升了。
3. **成本**：方向从 1 次调用降到 0 次。检索那一列的第二行是 0，是因为 query
   向量在第一组跑完时就进了缓存——那是缓存效应，不是隔离省的，如实记在这里。

## 途中修掉的一个真 bug：贴合门

第一版实测里出现过这样一次排序（隔离也拦不住）：一条**跨图**命中 cos = 0.497，
一条**本图**命中 cos = 0.9625，两条的 `norm` 并列（RRF 分相同），结果跨图的在前。
原因是 α 还乘了方向的权重：跨图那条"最像"的是重方向（权重 0.44 → α 0.15），
本图那条"最像"的是轻方向（权重 0.22 → α 0.075），于是 `0.497 × 0.15 > 0.9625 × 0.075`。

修法是加一道 `MIN_COSINE = 0.6` 的**贴合门**——余弦低于它就不算"属于这张图"。
这个数是从实测分布的空档里取的：

| 命中来自 | 本图材料的余弦 | 另一张图材料的余弦 |
|---|---|---|
| 图 B（碳中和） | 0.918 / 0.958 / 0.962 | 0.487 / 0.497 |
| 图 A（机器学习） | 0.843 / 0.916 / 0.927 | 0.518 |

0.52 ↔ 0.84 之间空着一大段，0.6 落在里面。隔离是让跨图命中的余弦**掉到门以下**，
门是让"掉到门以下"真的变成"不加分"——两件事一起才让跨图污染变成 0。

## 隔离之后，个性化还剩多少价值

这是这次改动最该被追问的一件事，所以单独记。

**剩下的那一层是真的，但它比"画像"这个词听起来的小得多。**

隔离之后，参与加权的向量全部来自这张图的材料。于是"画像"能为排序做的，只剩
**同一批材料内部**的相对偏好：这几条命中里，哪一条更像这张图的主体内容。它答不了
"这个人喜欢什么"，因为这张图的材料已经把这个人的偏好**编码在材料本身里**了。

实测里的证据是清楚的：本图加分 0.21–0.25，跨图加分 0。也就是说画像的全部话语权
都花在"这批材料内部谁更靠前"上，而这个信息**检索的相关性分其实也有**——它对
`norm` 的贡献远大于 α 的 0.15。画像在此刻是一个二阶修正，两次实测里它只搬动了
1 条相邻顺位。

所以判断是：**内容层没有被"隔离"救活，它被隔离降级成了一个 tie-breaker。**
一个只在 RRF 分并列时改变两条顺序的机制，撑不起"画像"这个名字，也撑不起它带来
的复杂度（一张表、一次聚类、一个开关、三道门）。真正在做内容个性化的是
"这张图的材料"本身——那是用户自己给的，不是系统猜的。

**那内容层该不该删？** 分两种情况：

- **如果"个性化"的目标是"让每张图更像它自己"**：那不需要画像这一层。材料的
  相关性排序已经在做这件事，画像只是重复了一遍，还多一个可能调错的 α。
- **如果目标是"跨图地学这个人"**：那就该**反着来**——保留全局方向，但把它用在
  **召回**（"这个人的其它图里有没有相关材料"）而不是**排序**。而约束 1 明确写了
  "不在召回用"，因为那是过滤气泡。

两条都指向同一个结论：**内容层（`profile_vectors` + `boost`）在隔离之后没有
剩下一个站得住的位置。** 这一轮按要求做了隔离（它把污染从 0.13 降到 0，是净收益），
但下一步该讨论的不是"隔离得够不够彻底"，而是"这一层还该不该存在"。

唯一能救它的方向是把它变成用户**看得见、能改**的东西（面板里列出这张图的几个
方向、让用户关掉其中一个），因为一个不可见、不可改、只搬动相邻顺位的机制，用户
无法判断它值不值得那 0.15。
